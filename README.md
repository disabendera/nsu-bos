# Lab 1

## Программа в файле `hello.c`

------------------------------------------------------------------------

## 1. Получаем исполняемый файл

``` bash
gcc -Wall -Wextra -Werror hello.c -o hello
```

------------------------------------------------------------------------

## 2. Проверяем, что файл исполняемый

``` bash
file hello
```

Вывод:

    hello: ELF 64-bit LSB pie executable, x86-64, version 1 (SYSV), dynamically linked, interpreter /lib64/ld-linux-x86-64.so.2, BuildID[sha1]=bcf29c35d981f3de82781475f0043d262f85828b, for GNU/Linux 3.2.0, not stripped

### Пояснение:

-   **ELF** --- Executable and Linkable Format\
-   **64-bit** --- архитектура x86-64\
-   **LSB** --- Little Endian\
-   **pie executable** --- Position Independent Executable (может быть
    загружен по случайному адресу --- ASLR)\
-   **dynamically linked** --- используется динамическая линковка\
-   **interpreter** --- путь к динамическому загрузчику

------------------------------------------------------------------------

## 3. Смотрим unresolved symbols

``` bash
nm -D hello
```

Команда анализирует таблицу динамических символов ELF-файла (`.dynsym`).

Вывод:

    U __libc_start_main@GLIBC_2.34
    U puts@GLIBC_2.2.5

### Пояснение:

-   **U (Undefined)** --- символ объявлен, но не определён в данном
    бинарнике\
-   Реализация функции будет найдена во время выполнения (runtime)

Таким образом:

-   `puts` отсутствует в бинарнике\
-   `__libc_start_main` --- инициализирующая функция из `libc`

### Почему нет `printf`?

Компилятор увидел, что в `printf` нет форматирования:

``` c
printf("Hello world\n");
```

и оптимизировал вызов в:

``` c
puts("Hello world");
```

------------------------------------------------------------------------

## 4. Смотрим зависимости

``` bash
ldd ./hello
```

Вывод:

    linux-vdso.so.1 (0x00007fffc74e8000)
    libc.so.6 => /lib/x86_64-linux-gnu/libc.so.6 (0x00007f4d81164000)
    /lib64/ld-linux-x86-64.so.2 (0x00007f4d8139a000)

### Пояснение:

#### linux-vdso.so.1

Virtual Dynamic Shared Object --- специальный объект, который ядро
отображает в память процесса для ускорения некоторых системных вызовов.

#### libc.so.6

GNU C Library --- содержит реализацию `puts`, `printf` и других
стандартных функций.

#### ld-linux-x86-64.so.2

Dynamic Loader (динамический загрузчик) --- программа, которая:

-   загружает динамические библиотеки
-   разрешает символы
-   выполняет relocation
-   настраивает таблицы GOT и PLT

------------------------------------------------------------------------

## 5. Запуск программы

``` bash
./hello
```

Вывод:

    Hello world

# Путь разрешения Undefined Symbols

------------------------------------------------------------------------

## 1. Компиляция

В коде вызывается `puts`.

Компилятор:

-   создаёт запись о символе в `.dynsym`
-   создаёт relocation-запись в `.rela.plt`
-   генерирует вызов `call puts@plt`
-   не знает реального адреса `puts`

В бинарнике отсутствует реальный адрес функции.

------------------------------------------------------------------------

## 2. execve()

Shell вызывает:

    execve("hello", ...)

Ядро:

1.  создаёт адресное пространство процесса\
2.  маппит все сегменты `LOAD`\
3.  видит сегмент `INTERP`\
4.  запускает `/lib64/ld-linux-x86-64.so.2`

------------------------------------------------------------------------

## 3. Dynamic Loader

`ld-linux`:

1.  читает секцию `.dynamic`\
2.  видит `NEEDED libc.so.6`\
3.  загружает `libc.so.6` в память\
4.  обрабатывает relocation-записи\
5.  подготавливает таблицы GOT и PLT

------------------------------------------------------------------------

## 4. GOT и PLT

### PLT --- Procedure Linkage Table

Таблица обёрток для вызова внешних функций.

В коде выполняется:

    call puts@plt

PLT не хранит реальный адрес функции, она выполняет переход через GOT.

------------------------------------------------------------------------

### GOT --- Global Offset Table

Таблица, в которой хранятся реальные адреса функций из динамических
библиотек.

------------------------------------------------------------------------

## 5. Первый вызов puts

1.  `main` вызывает `call puts@plt`\
2.  PLT обращается к записи в GOT\
3.  Если используется lazy binding:
    -   адрес ещё не заполнен\
    -   вызывается dynamic loader\
    -   он находит `puts` в `libc`\
    -   записывает реальный адрес в GOT\
4.  Выполняется `puts`

После первого вызова:

-   адрес в GOT уже заполнен\
-   последующие вызовы идут напрямую через GOT
