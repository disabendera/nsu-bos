# 2. Процесс и fork()

Процесс — это выполняемая программа с собственным:
- виртуальным адресным пространством
- таблицами страниц (page tables)
- набором VMA (Virtual Memory Areas)

## fork()

```c
pid_t pid = fork();
```

После fork():

- создаётся новый процесс
- копируются page tables (а не память)
- оба процесса продолжают выполнение

Различие:
- parent получает PID ребёнка
- child получает 0

---

# 3. Память после fork

После fork:

- виртуальные адреса одинаковые
- page table entries указывают на те же физические страницы
- страницы помечены read-only

👉 память физически не копируется

---

# 4. Copy-On-Write (COW)

Механизм:

1. процесс пытается записать в страницу
2. CPU вызывает page fault (write to RO)
3. ядро:
  - выделяет новую физическую страницу
  - копирует данные
  - обновляет PTE
4. страница становится:
  - private
  - dirty

---

# 5. Dirty страницы

Dirty = страница была изменена (записана)

Типы:

## Shared_Dirty
- изменена
- но разделяется между процессами

## Private_Dirty
- изменена
- принадлежит одному процессу

👉 рост Private_Dirty = признак COW

# 7. Интерпретация

Изменение:

Shared_Dirty: 56 → 52 kB  
Private_Dirty: 40 → 44 kB

👉 часть страниц:
- была shared
- стала private

Это означает:
👉 произошёл COW

# 8. Почему шаг ≈ 4 KB

Копирование идёт по страницам:

- размер страницы ≈ 4 KB
- даже изменение 1 байта копирует всю страницу

# 9. PSS (Proportional Set Size)

Определение:

PSS — это память, реально "принадлежащая" процессу с учётом shared

## Расчёт

- private страницы считаются полностью
- shared страницы делятся между процессами

Пример:

страница 4 KB, 2 процесса:
→ каждому по 2 KB

---

## Формула

PSS = Private + Shared / N

---

## Зачем нужен PSS

RSS(resident set size) переоценивает память (считает shared полностью)

PSS даёт реальную оценку

# 11. procfs

## /proc/<pid>/maps
- карта виртуальной памяти
- VMA (адреса, права, файлы)

## /proc/<pid>/smaps
- maps + статистика по каждой области

## /proc/<pid>/smaps_rollup
- агрегированная статистика по процессу

---

# 12. maps vs smaps

maps:
- показывает структуру виртуальной памяти
- не показывает COW

smaps:
- показывает поведение страниц
- отражает COW

# 14. Интерпретация состояний

S → sleeping  
Z → zombie

Zombie:

- процесс завершён
- осталась запись в таблице процессов
- ждёт wait()

# 15. wait()

wait():
- читает статус процесса
