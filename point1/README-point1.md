# Lab 3.1 --- Файлы и файловые системы

## Копирование каталога "задом наперёд"

### Суть задания

Программа получает путь к каталогу `src_dir` и:

1.  Создаёт каталог назначения `dst_dir` с именем, равным
    `reverse(basename(src_dir))`.
2.  Копирует **только regular files** из `src_dir` в `dst_dir`.
3.  При копировании:
    -   имя файла переворачивается
    -   содержимое файла копируется **в обратном порядке байтов**

Другие типы файлов (symlink, directory, device, socket, fifo)
**пропускаются**.

------------------------------------------------------------------------

# 1. Сборка и запуск

## Компиляция

``` bash
gcc -O2 -Wall -Wextra -Werror -std=c11 reverse_dir.c -o reverse_dir
```

Флаги:

флаг         значение
  ------------ -------------------------------
`-O2`        оптимизация
`-Wall`      предупреждения
`-Wextra`    дополнительные предупреждения
`-Werror`    warnings → errors
`-std=c11`   стандарт C

# 3. Алгоритм программы

## 3.1 Создание каталога назначения

    src_dir = parent + "/" + base
    rev_base = reverse(base)
    dst_dir = parent + "/" + rev_base
    mkdir(dst_dir, 0755)

------------------------------------------------------------------------

## 3.2 Обход каталога

    DIR *dir = opendir(src_dir)
    readdir(dir)

Структура:

    struct dirent {
        ino_t d_ino;
        unsigned char d_type;
        char d_name[];
    }

Записи `"."` и `".."` пропускаются.

------------------------------------------------------------------------

## 3.3 Определение типа файла

Используется

    lstat()

а не `stat()`.

функция   поведение
  --------- -----------------------------
stat      следует по symlink
lstat     возвращает тип самой ссылки

Проверка regular file:

    S_ISREG(st.st_mode)

------------------------------------------------------------------------

## 3.4 Копирование файла

    open(src_path, O_RDONLY)
    open(dst_path, O_WRONLY | O_CREAT | O_TRUNC)
    lseek + read + reverse(buffer) + write

Размер файла берётся из:

    struct stat
    st_size

------------------------------------------------------------------------

# 4. Почему используется блочное копирование

Чтение по одному байту:

    lseek
    read
    write

→ огромное число системных вызовов.

Чтение блоками (например 64KB):

-   меньше syscalls
-   меньше переключений user/kernel
-   быстрее.

## struct file

Описывает **открытый экземпляр файла**.

    struct file {
        struct inode *f_inode;
        loff_t f_pos;
        struct file_operations *f_op;
    }

------------------------------------------------------------------------

## struct inode

Метаданные файла.

    struct inode {
        umode_t i_mode;
        loff_t i_size;
    }

------------------------------------------------------------------------

## struct dentry

Элемент **dentry cache**.

    struct dentry {
        struct inode *d_inode;
        struct dentry *d_parent;
        struct qstr d_name;
    }

Используется для ускорения поиска файлов по имени.

# 6. Схема VFS (Virtual File System)

Linux использует слой **VFS**, который позволяет работать с разными
файловыми системами через единый интерфейс.

Основные структуры:

    superblock
       │
       ▼
    inode
       │
       ▼
    dentry
       │
       ▼
    file

### Значение структур

структура    роль
  ------------ ---------------------------
superblock   описание файловой системы
inode        метаданные файла
dentry       имя файла в каталоге
file         открытый файл

# 7. Как работает open()

Пользовательский вызов:

    open(path, flags)

glibc вызывает syscall:

    openat()

### Шаги внутри ядра

1.  CPU выполняет инструкцию `syscall`
2.  управление переходит в `__x64_sys_openat`
3.  выполняется **path lookup**
4.  ядро ищет имя в **dentry cache**
5.  если не найдено → читается каталог с диска
6.  находится `inode`
7.  создаётся `struct file`
8.  добавляется запись в `fdtable`
9.  возвращается file descriptor

------------------------------------------------------------------------

# 8. Как работает readdir()

`readdir()` внутри вызывает syscall:

    getdents64

Он читает содержимое каталога и возвращает записи:

    struct linux_dirent64 {
        ino64_t d_ino;
        unsigned char d_type;
        char d_name[];
    }

Эти записи затем преобразуются в `struct dirent` библиотекой libc.

------------------------------------------------------------------------

# 9. Как работает read()

Последовательность:

    read()
     ↓
    sys_read
     ↓
    vfs_read
     ↓
    filesystem read

Перед чтением ядро проверяет **page cache**.

------------------------------------------------------------------------

# 10. Cache hit и cache miss

### Cache hit

Страница файла **уже находится в page cache**.

    page cache → user buffer

Диск не используется.

------------------------------------------------------------------------

### Cache miss

Нужной страницы **нет в page cache**.

Тогда происходит:

    disk → DMA → RAM → page cache → user buffer

1.  формируется запрос к блочному устройству
2.  контроллер диска выполняет DMA
3.  данные попадают в RAM
4.  страница добавляется в page cache
5.  копируется в память процесса

------------------------------------------------------------------------

# 14. Возможные вопросы на защите

**Почему используется lstat, а не stat?**\
`stat()` следует по symlink. `lstat()` возвращает тип самой ссылки.

**Что такое file descriptor?**\
Индекс в таблице файлов процесса:

    fd → struct file

**Почему lseek не читает диск?**\
Он только изменяет поле `f_pos`.

**Почему read не всегда идёт на диск?**\
Из‑за page cache.

**Почему копирование делается блоками?**\
Чтобы уменьшить количество системных вызовов.
