# Лабораторная работа: Понятие пользователя. Управление правами.

**Тема:** Использование SUID-бита для доступа к файлам.

## 1. Создание файла с правами «чтение только владельцу»

Создаем рабочую директорию, переходим в нее и создаем текстовый файл `secret.txt` с секретным сообщением. Устанавливаем права `400` (чтение разрешено только владельцу файла, в данном случае — `root`).

```bash
mkdir /tmp/suid_lab
cd /tmp/suid_lab
chmod 777 .
echo "Это секретные данные, доступные только владельцу." > secret.txt
chmod 400 secret.txt
```

Проверка прав:
```bash
ls -l secret.txt
# -r-------- 1 root root 87 May 14 18:20 secret.txt
```

## 2. Написание программы

Создаем файл `reader.c`. Программа выводит реальный и эффективный идентификаторы пользователя (UID), а затем пытается открыть и прочитать содержимое файла `secret.txt`.

```c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/types.h>

int main() {
    uid_t ruid = getuid();
    uid_t euid = geteuid();

    printf("Реальный UID (RUID): %d\n", ruid);
    printf("Эффективный UID (EUID): %d\n", euid);

    FILE *file = fopen("secret.txt", "r");
    if (file == NULL) {
        perror("Ошибка при открытии файла");
        return 1;
    }

    char buffer[256];
    printf("Содержимое файла:\n");
    while (fgets(buffer, sizeof(buffer), file) != NULL) {
        printf("%s", buffer);
    }

    fclose(file);
    return 0;
}
```

Компилируем программу:
```bash
gcc reader.c -o reader
```

## 3. Запуск программы без SUID-бита

Запускаем программу от имени владельца (`root`):
```bash
root@v653137:/tmp/suid_lab# ./reader
Реальный UID (RUID): 0
Эффективный UID (EUID): 0
Содержимое файла:
Это секретные данные, доступные только владельцу.
```

Запускаем программу от имени чужого пользователя (используем системного бесправного пользователя `nobody`):
```bash
root@v653137:/tmp/suid_lab# sudo -u nobody ./reader
Реальный UID (RUID): 65534
Эффективный UID (EUID): 65534
Ошибка при открытии файла: Permission denied
```

## 4. Объяснение результата (до установки SUID)

При стандартном запуске исполняемого файла ядро операционной системы назначает процессу **эффективный идентификатор (EUID)**, равный **реальному идентификатору (RUID)** пользователя, который инициировал запуск.

Операционная система проверяет права доступа к файлам, основываясь именно на EUID процесса.
* В первом случае (запуск от `root`) EUID = 0 совпадает с владельцем файла `secret.txt`. Доступ разрешен.
* Во втором случае (запуск от `nobody`) EUID = 65534. Процесс пытается получить доступ к файлу, принадлежащему пользователю `root`. Так как для остальных пользователей права на чтение отсутствуют (установлено `400` или `-r--------`), ядро блокирует системный вызов `open`, и функция `fopen` возвращает ошибку `Permission denied`.

## 5. Установка SUID-бита

Устанавливаем SUID-бит на бинарный файл `reader`, добавляя право `s` для владельца:
```bash
root@v653137:/tmp/suid_lab# chmod u+s reader
root@v653137:/tmp/suid_lab# ls -l reader
-rwsr-xr-x 1 root root 16312 May 14 18:25 reader
```
Символ `s` в правах владельца (`-rws...`) подтверждает успешную установку SUID-бита.

## 6. Запуск программы с установленным SUID-битом

Снова запускаем программу от имени бесправного пользователя `nobody`:
```bash
root@v653137:/tmp/suid_lab# sudo -u nobody ./reader
Реальный UID (RUID): 65534
Эффективный UID (EUID): 0
Содержимое файла:
Это секретные данные, доступные только владельцу.
```

## 7. Объяснение результата (после установки SUID)

Наличие SUID-бита у исполняемого файла радикально меняет логику назначения эффективного идентификатора процесса.

При запуске программы пользователем `nobody`:
1. **Реальный UID (RUID)** устанавливается в значение `65534`, так как именно этот пользователь фактически запустил процесс.
2. **Эффективный UID (EUID)** устанавливается в значение `0` (UID владельца исполняемого файла, то есть `root`), а не в значение пользователя, запустившего программу.

Поскольку проверка прав на чтение файла `secret.txt` осуществляется ядром на основе EUID процесса, система видит, что процесс работает с эффективными правами суперпользователя (EUID = 0). Это значение совпадает с владельцем секретного файла. В результате ядро предоставляет доступ, и программа успешно читает и выводит содержимое, несмотря на то, что изначально запуск был инициирован непривилегированным пользователем.
