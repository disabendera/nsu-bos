# Lab 5.2 — Процесс в состоянии zombie

---

# 1. Создание zombie-процесса

## Код

```c
pid_t pid = fork();

if (pid == 0) {
    exit(5);
} else {
    sleep(30);   // нет wait()
}
```

---

## Наблюдение

```bash
ps -o pid,ppid,state,cmd -p 3664,3665
```

Результат:

```
PID    PPID S CMD
3664   2876 S ./lab5-point2-cz
3665   3664 Z [lab5-point2-cz] <defunct>
```

---

## Интерпретация

- 3665 → дочерний процесс
- состояние `Z` → zombie
- `<defunct>` → процесс завершён, но не удалён

---

# 2. Что происходит при завершении процесса

При вызове:

```c
exit(code);
```

ядро выполняет:

1. освобождает пользовательскую память
2. закрывает ресурсы
3. сохраняет:
    - exit_code
    - статус завершения
4. переводит процесс в состояние:

```
EXIT_ZOMBIE
```

---

# 3. Что остаётся у zombie

В системе остаётся часть `task_struct`:

- PID
- PPID
- exit_code
- статус

👉 память процесса уже освобождена

---

# 4. Какую проблему решает zombie

Проблема:

после завершения процесса родитель должен получить:

- код завершения
- причину завершения

Если бы процесс удалялся сразу:

- родитель не смог бы получить статус
- wait() не имел бы данных

---

## Решение

Zombie сохраняет информацию до вызова:

```c
wait()
```

---

# 5. Механизм wait()

```c
wait(&status);
```

ядро:

1. находит zombie-процесс
2. копирует status родителю
3. вызывает release_task()
4. удаляет процесс полностью

---

# 6. Родитель тоже может стать zombie

## Эксперимент

```bash
ps -o pid,ppid,state,cmd -p 3702,3703,3704
```

Результат:

```
PID    PPID S CMD
3702   2876 S ./lab5-point2-pz
3703   3702 Z [lab5-point2-pz] <defunct>
3704   2871 S ./lab5-point2-pz
```

---

## Интерпретация

- 3703 → parent, zombie
- 3702 → grandparent, жив
- 3704 → child, жив

---

# 7. Что происходит в этой ситуации

1. parent завершился → стал zombie (так как grandparent не вызвал wait)
2. child остался жив
3. ядро выполнило reparenting

---

# 8. Reparenting (переподвешивание)

Если родитель умирает, а child жив:

- child становится orphan
- ядро назначает нового родителя

Обычно:
- PID 1 (init/systemd)
  или другой reaper-процесс

---

В эксперименте:

```
PPID child: 3702 → 2871
```

👉 child переподвешен

---

# 9. Ключевые механизмы ядра

- do_exit() → перевод в EXIT_ZOMBIE
- task_struct сохраняется частично
- wait()/wait4() → чтение exit_code
- release_task() → удаление процесса
- reparenting → смена PPID для orphan

---

# 10. Вывод

- zombie — это завершённый процесс с сохранённым статусом
- нужен для передачи exit_code родителю
- удаляется только через wait()
- любой процесс может стать zombie
- при смерти родителя child переподвешивается другому процессу
